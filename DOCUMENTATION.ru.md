# Yuki System — Полная документация

Этот документ описывает экосистему Yuki целиком: архитектуру, роль каждого модуля, протокол
обмена сообщениями, модель безопасности и порядок развёртывания системы от начала до конца.
Краткий обзор - в [README.md](README.md). `yuki-speaker` - отдельный, более старый модуль на
ESP32, не охваченный ни этим документом, ни этапом усиления защищённости экосистемы к релизу
1.0.0.

## 1. Архитектура

```text
                              ┌─────────────┐
                              │  yuki-core  │  Python/asyncio WebSocket-сервер
                              │  («мозг»)   │  ws://host:8000  (/device, /webui)
                              └─────────────┘
                                     │
                  ┌──────────────────┼─────────────────┐
                  │                  │                 │
          ┌───────▼───────┐  ┌───────▼──────┐  ┌───────▼───────┐
          │ yuki-webui    │  │  Устройства  │  │ yuki-protocol │
          │ Flask +       │  │  (/device)   │  │ общий SDK,    │
          │ JS в браузере │  │              │  │ свой для      │
          │ (/webui)      │  │              │  │ каждого языка │
          └───────────────┘  └──────────────┘  └───────────────┘
                 ┌───────────────────┼─┬─────────────────────────┬──────────────────────┐
                 │                     │                         │                      │
        ┌────────▼───────┐  ┌──────────▼──────────┐  ┌───────────▼──────────┐  ┌────────▼────────┐
        │ yuki-device-pc │  │ yuki-device-android │  │ yuki-device-pc-linux │  │ yuki-humidifier │
        │ (Windows, C#)  │  │ (Kotlin)            │  │ (Python/GTK4/        │  │ (ESP32-C3, C++) │
        │                │  │                     │  │ libadwaita)          │  │                 │
        └────────────────┘  └─────────────────────┘  └──────────────────────┘  └─────────────────┘
```

`yuki-core` - единственный компонент, с которым напрямую взаимодействуют все остальные модули.
Устройства подключаются к `/device`, аутентифицируются общим bearer-токеном и обмениваются
статусами/командами/метриками. Браузеры подключаются к `/webui` (статическую панель управления
им отдаёт Flask-приложение `yuki-webui`) и после аутентификации собственным токеном получают то
же самое представление в реальном времени плюс административные действия (одобрение устройств,
ротация токена, просмотр журнала аудита, ...).

## 2. Модули

| Модуль | Язык | Роль |
|---|---|---|
| [`yuki-core`](../yuki-core) | Python | Сервер: маршрутизация, аутентификация/авторизация устройств, хранение метрик и журнала аудита, ротация токена |
| [`yuki-protocol`](../yuki-protocol) | Python / C# / JavaScript / C++ | Общий формат сообщений, реализованный на каждом языке |
| [`yuki-webui`](../yuki-webui) | Python (Flask) + JS | Веб-панель управления: список устройств, группы, теги, виджеты, настройки |
| [`yuki-device-pc`](../yuki-device-pc) | C# (WinForms) | Клиент удалённого управления для Windows |
| [`yuki-device-pc-linux`](../yuki-device-pc-linux) | Python (GTK4/libadwaita) | Клиент удалённого управления для Linux, тот же набор возможностей, что у Windows-клиента |
| [`yuki-device-android`](../yuki-device-android) | Kotlin | Клиент удалённого управления для Android |
| [`yuki-humidifier`](../yuki-humidifier) | C++ (Arduino/ESP32) | Прошивка умного увлажнителя |

## 3. Протокол

Весь трафик WebSocket - это JSON, одно сообщение на кадр, без бинарного фрейминга:

```json
{"protocol": "yuki/1.0", "type": "...", "id": "...", "timestamp": 0, "payload": {}}
```

Поле `type` определяет смысл сообщения (`hello`, `welcome`, `status`, `command`,
`command_result`, `metrics`, `device_to_device`, ...). Каждая реализация проверяет, что
`protocol` равно ровно `yuki/1.0`, и отклоняет любое другое значение - никакого механизма
совместимости между версиями нет, поэтому в рамках одного развёртывания следует использовать одну
версию протокола повсюду. Полный каталог сообщений - в README самого
[`yuki-protocol`](../yuki-protocol).

## 4. Модель безопасности

- **Аутентификация устройств**: общий bearer-токен (`auth_token`, генерируется `yuki-core` и
  распространяется на каждое устройство отдельно, вне общего канала связи - скопируйте
  содержимое `.token` или задайте `YUKI_AUTH_TOKEN` самостоятельно). Сравнивается с помощью
  проверки за постоянное время.
- **Авторизация устройств**: предъявления корректного токена самого по себе недостаточно - новое
  для `yuki-core` устройство остаётся в очереди на подтверждение, пока администратор не одобрит
  его в `yuki-webui` (либо оно заранее не добавлено в список авторизованных). Устройства также
  можно полностью занести в чёрный список.
- **Вход в WebUI**: `yuki-webui` поставляется с логином по умолчанию `admin`/`admin` (хранится на
  диске в виде хеша, а не открытым текстом) - смените его на панели «Настройки» сразу после
  входа. Собственный сокет браузера `/webui`, работающий в реальном времени, с `yuki-core`
  требует отдельного рукопожатия с токеном (он запрашивается у `yuki-webui` только после того,
  как вы уже вошли в систему), поэтому неаутентифицированный браузер не может достучаться до
  этого управляющего сокета.
- **Списки разрешённых команд**: каждый клиент (PC, Linux, Android, увлажнитель) заявляет, какие
  команды он готов выполнять, и локально отказывается от всего, чего нет в этом списке,
  независимо от того, что разрешает `yuki-core` - скомпрометированный или неправильно
  настроенный сервер не может заставить устройство выполнить команду, которую его владелец явно
  отключил.
- **Шифрование транспорта**: **везде отключено по умолчанию** (обычные `ws://`/`http://`), как и
  положено для типичного развёртывания домашней автоматизации в доверенной локальной сети.
  Каждый компонент поддерживает включение TLS - `yuki-core`
  (`YUKI_TLS_ENABLED`/`YUKI_TLS_CERT`/`YUKI_TLS_KEY`), `yuki-webui`
  (`YUKI_WEBUI_TLS_ENABLED`/...), `yuki-humidifier` (`ENABLE_TLS` в `Config.h`), а настольные и
  мобильные клиенты - просто через адрес `wss://`/`https://` - точные имена переменных см. в
  README каждого модуля.
- **Хранение секретов**: токен ядра и учётные данные webui хранятся с ограниченными правами
  доступа к файлам (600) и, где это применимо, в виде хеша (пароль webui); Windows-клиент
  шифрует хранимый токен с помощью DPAPI.

Ничто из перечисленного не заменяет запуск экосистемы в сети, которой вы действительно доверяете
(ваша домашняя локальная сеть, VPN, ...) - это поднимает планку того, что устройство или браузер
в этой сети могут сделать друг с другом, но не превращает `yuki-core` во что-то безопасное для
прямой публикации в открытый интернет.

## 5. Настройка развёртывания

1. Запустите `yuki-core` (см. его README) - запомните сгенерированный токен в `.token` либо
   задайте `YUKI_AUTH_TOKEN` самостоятельно перед первым запуском.
2. Запустите `yuki-webui`, войдите под `admin`/`admin` и смените пароль в «Настройках».
3. Настройте каждое устройство (увлажнитель - через собственную страницу настройки точки
   доступа, клиенты PC/Linux/Android - через свой интерфейс), указав адрес `yuki-core` и токен
   из шага 1.
4. Новые устройства появляются в `yuki-webui` в очереди на подтверждение - одобрите их там.
5. При желании включите TLS повсеместно, когда развёртывание уже работает без него - см. README
   каждого модуля.
